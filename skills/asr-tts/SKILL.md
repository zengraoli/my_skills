# 语音识别与合成

本 skill 目录：`SKILL.md`（本流程）、`speech.py`（脚本）、`.env`（key 与默认配置）、`README.md`（人看的说明）。

## 第 0 步：环境检查


## 第 1 步：认需求，选命令

| 用户想要 | 命令 | 费用 |
|---|---|---|
| 录音 / 视频转文字 | `asr --file x.mp3` | Standard ¥1.8/小时 |
| 出字幕 | `asr --file x.mp4 --format srt` | 同上 |
| 会议纪要（谁说了什么） | `asr --file x.mp3 --model pro --speakers 4 --format srt` | Pro ¥3.6/小时 |
| 边转写边翻译 | `asr --file x.mp3 --model pro --translate en --format srt` | Pro |
| **提取歌词** | `lyrics --file 歌.mp3 --out 目录/歌名` | Standard，一首 4 分钟约 ¥0.12 |
| 念一段话 / 配音 | `tts --text "..." --out x.mp3` 或 `tts --file 稿.txt --out x.mp3` | 商汤 ¥3.5/万字符（汉字算 2），edge 免费 |
| 看有哪些音色 | `voices [--provider edge]` | 免费 |

## 模型怎么选

- **standard（默认）**：逐字 + 逐句时间戳、标点。转文字、出字幕、提歌词都用它。
- **pro**：多了说话人区分和翻译，贵一倍。
- **lite**：只有文字、没有时间戳，最便宜，不能出字幕和歌词。
- **deepthink**：会把口语改写成书面语（去掉"嗯啊"、重组句子）——**适合整理讲话稿，绝不能用来提歌词**。

## 提取歌词的要点

- 脚本会自动把歌切成 ≤170 秒的段（在换气或间奏处下刀）再分别识别。原因：商汤服务端按 180 秒一个窗口处理，超出的窗口有时**文字对但时间戳丢失**，整段歌词会没有时间轴。
- 按识别结果自带的标点断成乐句，再对齐逐字时间戳生成 `.lrc`；过长的句子在最大停顿处拆开（`--max-chars` 调）。
- 伴奏会造成**同音错字**（实测"古柏"认成"故柏"、第二遍副歌错得更多），交付时提醒用户对照原曲校对；要更准，先用 suno-music 的 `stems` 分出人声再提取。
- 输出三个文件：`歌名.txt`（纯歌词）、`歌名.lrc`（带时间轴，播放器可滚动显示）、`歌名.asr.json`（原始识别结果）。

## TTS 的要点

- `.env` 的 `TTS_PROVIDER` 决定默认用谁；`--provider edge` 临时切到免费的 edge-tts（男声 `zh-CN-YunxiNeural`）。
- 长文本自动按句切段合成再拼接。

## 已知坑

- 单个文件上限 10 MB，脚本会自动压成单声道 16 kHz；太长的音频自动切段。
- 说话人区分对歌唱基本无效，别拿它分析"谁唱了哪句"。
- 不要在聊天里索要 key，缺 key 让用户填 `.env`。
