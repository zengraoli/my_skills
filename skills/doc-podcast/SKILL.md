# 文档 → 双人播客

流程：0 环境检查 → 1 读素材 → 2 写对谈脚本 → 3 背景音乐三选一 → 4 渲染 → 5 验收。本 skill 目录：`SKILL.md`（本流程）、`podcast.py`（渲染脚本）、`.env`（key 与默认配置）、`README.md`（人看的说明与能力边界）。

## 第 0 步：环境检查

```
python "<本 skill 目录>/podcast.py" check
```

缺 key、缺 ffmpeg 会逐项提示。缺 `.env` 时让用户在本目录建一个填 `SENSEAUDIO_API_KEY`，不要在聊天里索要 key。

## 第 1 步：读素材

- 用户给文件就读文件，给 URL 就抓正文，给主题就用你的搜索工具查 3–5 组不同角度（和 explainer-video 第 1 步同一套规矩：**至少一个真实数字或案例**，记来源）。
- 提炼成 3–5 个话题点，每个点带一个具体例子或数字。对谈的信息密度靠这个，不靠形容词。
- 素材太薄（不足以撑 3 个话题）先问用户要更多，别硬编。

## 第 2 步：写对谈脚本

写成 UTF-8 文本文件 `output/podcast/<标题>.txt`，格式：

```
# 标题：让AI替你值夜班
# 角色：小满=female_0038_b|主持人，亲切、语速略快、爱追问
# 角色：阿川=male_0029_a|嘉宾，沉稳、爱举例
# 场景：两人在安静的播客录音室对谈

小满：（热情）大家好，欢迎收听今天的节目。阿川，你最近……
阿川：（笑）简单说，它能让 AI 自己定闹钟。……
```

规矩：

- **两位主播固定人设**：一个主持人负责提问、复述、承接；一个嘉宾负责解释、举例。默认音色 `female_0038_b` + `male_0029_a`，用户要换从 https://docs.senseaudio.cn/guides/voice/catalog 选。最多 3 个角色（平台限制）。
- **结构**：开场（10 秒内点题）→ 每个话题点一轮"问—答—追问—例子" → 收尾（一句总结 + 预告/告别）。
- **长度**：约 4.7 字/秒。5 分钟 ≈ 1400 字，10 分钟 ≈ 2800 字。先问用户要几分钟，默认 5 分钟。
- **台词**：口语、短句，每行 20–80 字；主持人的反应要具体（"七天，这个时间还挺合理的"），别只写"嗯，明白了"。括号里写情绪/语气（`（笑）`、`（好奇）`、`（放慢）`），不会被念出来。
- **不要**在台词里写任何方括号标签；引号用逗号或"某某说"替代；英文缩写可以，整句英文和命令行别写。
- 脚本用文件写入工具写，别通过 shell 灌文本。

## 第 3 步：背景音乐三选一（必须问用户）

渲染前问用户一句："背景音乐要 **无 / 自备 / 生成**？"，把答案写进脚本的 `# 背景音乐：` 行（或渲染时用 `--bgm` 传）：

| 用户选 | 脚本里写 | 你要做的 |
|---|---|---|
| 无 | `# 背景音乐：无` | 什么都不加，NotebookLM 就是这种干聊风格 |
| 自备 | `# 背景音乐：文件名.mp3` | 让用户把音乐文件放进**项目根目录的 `input/`**（没有就建一个）并告诉你文件名；脚本会先在当前目录、再在 `input/` 里找，找不到会列出 `input/` 现有的音频文件 |
| 生成 | `# 背景音乐：生成` 或 `# 背景音乐：生成：轻快电子` | 脚本自动调用同级的 music-gen skill 出一段 120 秒纯音乐（约 0.5 元）存到 `output/music/podcast_bgm.mp3`，已存在则复用。music-gen 不存在时脚本会报错并给出安装方式（`git clone https://gitee.com/zengraoli/my_skills.git`，把 `skills/music-gen` 放到本 skill 同级），此时转告用户，或改为自备 |

用户没表态就默认"无"，并在报告里说明可以随时用 `--reuse-chunks --bgm …` 免费补上。

## 第 4 步：渲染

先 dry-run 看分段和预算，再真渲染：

```
python "<本 skill 目录>/podcast.py" render --script output/podcast/<标题>.txt --dry-run
python "<本 skill 目录>/podcast.py" render --script output/podcast/<标题>.txt [--bgm 音乐.mp3]
```

- 脚本按约 450 字自动分段（单次接口上限 120 秒），每段都带同一份角色定义，音色全程一致；段间 0.5 秒静音。
- **背景音乐按第 3 步的选择处理**：有音乐时会循环、压到 -18 dB、人声进入前留 2.5 秒纯音乐、随人声自动闭音、结尾淡出（`--bgm-gain`、`--bgm-intro` 可调）。脚本里的 `# 音乐：` 元信息会把 `[背景音乐]` 写进 A1 提示词，实测只会零星加一点装饰音，**不能当作背景乐**，一般别用。
- 输出：`output/podcast/<标题>.mp3`、`<标题>.srt`（每句带说话人）、`<标题>_script.txt`、`<标题>_chunks/`（每段 mp3 + 提示词 + 返回 json，可复现），末尾打印费用。
- 一段生成约 1–1.5 分钟；接口返回 429/5xx 脚本会自动等待重试。
- 只想换背景乐或改混音参数时加 `--reuse-chunks`，脚本没改的段不会重新生成、不扣费；改了台词的段会自动重生成。

## 第 5 步：验收与报告

用 ffprobe 确认总时长；打开 srt 抽查前几句和分段交界处的说话人是否对得上；报告文件路径、时长、话题结构、费用，以及第 1 步用到的事实来源。

## 已知坑

- 字幕接口不返回说话人，脚本按台词行顺序对齐；如果一行台词里混了两个人的话（比如"阿川说……"）会归错，一行只写一个人。
- 台词里的数字、英文缩写偶尔被念得不自然，可以在括号里提示读法或改成中文。
- `[背景音乐]`/`[音效]` 标签行为不稳定，不要依赖；音效想要的话另用 SenseAudio 音效接口生成再叠。
- 单段超过约 560 字会顶到 120 秒上限，脚本默认 450 字有余量，别调太大。
